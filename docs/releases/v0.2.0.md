# trading-indicators v0.2.0

**Released 2026-10-06** · [Full changelog](../../CHANGELOG.md#020---2026-10-06)

The **common indicator set** release. With RSI, Bollinger Bands and MACD added,
this repository now covers the indicators that essentially every charting
platform ships with — each one specified once, vector-tested, and portable.

Highlights:

- **Three new indicators**, each with a spec, shared vectors, a Python port and a
  test suite: **RSI**, **Bollinger Bands** and **MACD**.
- **Continuous integration**: the suite runs on Python 3.9–3.13, plus a Ruff lint
  job, on every push and pull request.
- **Release automation**: pushing a `v*` tag tests the commit and publishes these
  notes as the GitHub release.
- **Community scaffolding**: a code of conduct, citation metadata, and
  pull-request / issue templates that encode the spec-first process.

## New indicators

### RSI — Relative Strength Index

`rsi(close, period=14)` → one `0–100` series.

The spec pins down the details that implementations get wrong: Wilder's
smoothing (an exponential average with α = 1/period) seeded with the *simple*
average of the first `period` changes. Warm-up is the first `period` values, and
the degenerate cases are defined rather than left to a division-by-zero:
`avg_loss == 0` yields `100`, and a strictly falling market yields `0`.

```python
from indicators import rsi

rsi(close, 14)
# 0-100 momentum oscillator; the first `period` values are None
```

### Bollinger Bands

`bollinger(close, period=20, num_std=2)` → a `BollingerBands(middle, upper, lower)`
value object.

The moving average is the SMA, and the bands sit `num_std` **population**
standard deviations away (dividing by `period`, not `period - 1`) — the
convention charting platforms use, so the numbers here match what a trader sees
on a chart. Warm-up is the first `period - 1` values, and `num_std=0` collapses
the bands onto the middle line, which the vectors assert explicitly.

### MACD — Moving Average Convergence Divergence

`macd(close, fast_period=12, slow_period=26, signal_period=9)` → a
`MACDResult(macd, signal, histogram)` value object, i.e. the fast/slow EMA spread,
its signal EMA, and the difference between them.

The subtle part is warm-up, and the spec fixes it: the MACD line is defined from
index `max(fast, slow) - 1`, and because the signal line is an EMA *of the
defined region only*, the signal and histogram are defined from
`slow + signal - 2` (33 with the classic periods). A test case covers a signal
period longer than the available history, and another covers `fast == slow`
(where the MACD line is identically zero).

## Engineering

- **Shared test helpers.** `python/tests/_vectors.py` centralises loading the
  JSON vectors, so each test file is a thin description of its cases instead of
  repeated glob/JSON boilerplate.
- **Reproducible versioning.** The version now lives in exactly one place —
  `python/src/indicators/_version.py` — read by the build via
  `[tool.setuptools.dynamic]` and re-exported as `indicators.__version__`.
- **Linting.** Ruff is configured for `py39` with an 88-column line limit; the
  whole tree complies (checked with `ruff` in CI).
- **Documentation.** The root README gained CI/license/Python badges, a
  development section and links to the changelog, these release notes and the
  code of conduct.

## Upgrade notes

Nothing breaks — no public signature changed in this release. If you read the
version programmatically, note that it moved:

```python
import indicators

indicators.__version__  # "0.2.0" — read from indicators._version
```

`pyproject.toml` no longer carries a literal `version =`, so anything that
parsed the file rather than the metadata should switch to the package attribute
or `importlib.metadata`.

## Known limitations

- Python remains the only port; MQL5 and Pine Script are planned. The specs and
  vectors are already language-neutral, so a new port is a translation plus a
  runner that replays the same JSON.
- The indicators return plain Python lists of `float | None`; there is no NumPy
  or pandas integration yet, and no streaming / incremental (`update`) API.
