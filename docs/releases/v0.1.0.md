# trading-indicators v0.1.0

**Released 2026-10-04** · [Full changelog](../../CHANGELOG.md#010---2026-10-04)

The first release. It establishes the repository's core idea — *one
language-agnostic specification per indicator, one set of shared test vectors,
many language ports that must all agree* — and proves it with four indicators.

## Highlights

- **A spec-first monorepo.** Every indicator is defined once in `specs/<name>.md`
  (formulas, warm-up boundary, edge cases) with machine-readable vectors in
  `specs/vectors/<name>.json`. A port is a faithful translation of that spec, and
  its test suite replays the shared vectors. Nothing is hard-coded per language,
  so ports cannot silently drift apart.
- **Four indicators**, each with a spec, vectors, a Python port and tests:
  - **SMA / MA** — the classic unweighted moving average.
  - **EMA** — seeded with the SMA of the first `period` values, so the series is
    reproducible rather than dependent on the first close.
  - **ADX** — Wilder's trend strength, built on Wilder-smoothed `+DI` / `-DI`.
  - **Ichimoku Kinko Hyo** — Tenkan, Kijun, Senkou Span A/B and Chikou, with the
    cloud displacement applied to the returned series (chart-aligned output).
- **A self-contained Python port** under `python/`, with no runtime dependencies
  and `pytest` as the only test requirement.

## Notes

- Warm-up conventions are stated per spec instead of being left to the
  implementation: leading values that the indicator cannot yet define are
  `null` in the vectors and `None` in Python.
- Output containers are small value objects (`IchimokuResult`) so multi-line
  indicators return named series rather than bare tuples.

## Known limitations

- Python is the only port so far; MQL5 and Pine Script are planned.
- No packaging or lint configuration yet — those arrive in v0.2.0.
